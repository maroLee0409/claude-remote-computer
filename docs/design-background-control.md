# 뒤에서 조작하기(`--bg`)와 `launch` — 설계 기록

사용자가 마우스·키보드로 자기 일을 하는 동안, Claude 가 사내 MES 를 대신 조작하게 만든 기록이다.
무엇을 왜 골랐는지, 무엇을 버렸는지, 해 보니 어디서 깨졌는지를 남긴다.

## 요구

1. **창을 앞으로 가져오지 않는다.** 사용자가 쓰는 마우스·키보드·포커스를 뺏지 않는다.
2. **값 입력까지 된다.** 누르기만이 아니라 입력칸에 글자를 넣는 것까지.
3. **확인하는 과정도 앞으로 오지 않는다.** 눌렀는지 보려고 캡처할 때도 마찬가지.
4. **Claude 를 그냥 켰을 때 된다.** Claude Code 를 관리자 권한으로 띄우지 않는다.

대상은 WinForms + DevExpress 로 만든 MES 다. 메뉴·버튼은 직접 그린 컨트롤이다.

## 원래 방식이 왜 안 되나

기존 `click`·`key`·`type` 은 `SendInput` 으로 **진짜** 마우스·키보드를 움직인다.
그래서 `--focus` 로 그 창을 앞으로 가져와야 하고, 그동안 사람이 마우스를 움직이면 클릭이 엉뚱한 데 떨어진다.
요구 1 과 정면으로 부딪힌다.

## 검토한 방법

| 방법 | 결과 |
|---|---|
| UI Automation (`ui invoke`) | MES 메뉴·버튼은 전부 이름 없는 `Pane`, 패턴 없음, AutomationId 는 숫자 핸들(실측 34개 전부). 못 쓴다. 단, 로그인 창처럼 표준 컨트롤(Edit·ComboBox)인 곳은 잡힌다 → 되는 곳은 `ui` 를 먼저 쓴다 |
| `SendInput` + 앞으로 가져오기 | 진짜 입력이라 사람과 공유할 수 없다. 요구 1 위반 |
| **`PostMessage` + `PrintWindow`** | **채택.** 그 창에 메시지만 보내고, 그 창만 그려 받는다. 커서·포커스를 안 건드린다 |
| 자기 자신에게 RDP / 별도 데스크톱 | 무겁고, Windows Pro 는 세션이 하나라 같이 못 쓴다. 보류 |

## 채택한 설계

| 하는 일 | 방법 | 이유 |
|---|---|---|
| 보기 `shot --bg` | `PrintWindow(PW_RENDERFULLCONTENT)` | 다른 창에 가려져 있어도 그 창 내용이 찍힌다. 화면 캡처(`ImageGrab`)는 가린 창이 찍힌다 |
| 누르기 `click --bg` | 좌표 → 그 창의 **자식만** 따라 내려가 가장 안쪽 자식에 `WM_MOUSEMOVE`·`WM_LBUTTONDOWN`·`WM_LBUTTONUP` | `WindowFromPoint` 를 쓰면 그 자리를 덮은 다른 창으로 간다 |
| 넣기 `type --bg` | `GetGUIThreadInfo` 로 그 창 스레드의 포커스 칸 → `WM_CHAR`(UTF-16 단위) | 포커스는 스레드마다 기억돼서 창이 뒤에 있어도 남아 있다. 한글도 IME 없이 들어간다 |
| 키 `key --bg` | `WM_KEYDOWN`/`WM_KEYUP` 하나 | 엔터·탭·F5 정도 |
| 기다리기·확인 `waitstable --bg` | `PrintWindow` 를 반복 비교 | 요구 3. 확인도 앞으로 안 가져온다 |
| 좌표 | 스크린샷 좌표 그대로. `shot --bg` 가 PNG 에 창 원점을 적어 `--img` 로 되돌린다 | 좌표계를 하나로 유지한다는 원래 원칙 |

## 해 보고 알게 된 한계

1. **다른 창에 덮인 버튼은 안 눌린다.** WinForms 는 마우스를 뗄 때 `WindowFromPoint(그 자리) == 자기 자신` 일 때만 Click 을 낸다.
   입력칸 클릭·글자 입력은 이 검사가 없어서 덮여 있어도 된다.
   → **앞으로 올 필요는 없고, 누를 자리만 화면에 보이면 된다.** 사람은 1번 모니터, MES 는 2번 모니터에 둔다.
   덮인 자리를 누르면 `click --bg` 가 경고를 찍는다.
   (시험: 시험 창 전체를 빨간 창으로 덮으면 버튼이 안 눌리고, 오른쪽 절반만 덮으면 왼쪽 버튼은 눌린다.)
2. **안 눌려도 오류가 없다.** 메시지는 갔고 앱이 버린 것이라 알 길이 없다 → 누를 때마다 `shot --bg` 로 확인한다.
3. **조합키(Ctrl+S 등)는 안 된다.** 앱이 `GetKeyState` 로 진짜 키보드 상태를 본다. 단축키 대신 그 버튼을 누른다.
4. **최소화된 창은 안 된다.** 그리지 않으니 찍을 수도 누를 수도 없다. 뒤로 보내는 건 된다.
5. **관리자 권한으로 뜬 앱은 전부 막힌다.** 아래.

## 권한 문제 — 왜 `launch` 를 만들었나

**사실.** 사이트용 MES 실행 파일의 매니페스트가 `requireAdministrator` 다. 띄울 때마다 UAC 를 거쳐 관리자(High)로 뜬다.
Claude 는 일반 권한(Medium)이다. Windows(UIPI)는 낮은 권한에서 높은 권한 창으로 가는 입력·메시지·그리기를 막는다.
`PrintWindow` 는 오류 5, `PostMessage` 도 오류 5, `SendInput` 은 **오류 없이** 버려진다.

**선택지.**

| 선택지 | 판단 |
|---|---|
| Claude Code 를 관리자로 띄운다 | **기각.** 에이전트가 돌리는 모든 셸 명령이 관리자 권한이 된다. 실수 하나가 시스템 전체로 번진다. 요구 4 에도 어긋난다 |
| 설치 폴더 권한을 풀어 준다 | 기각. 보안 설정 변경이고, 매니페스트가 관리자를 요구하는 건 그대로라 효과도 없다 |
| UAC 자동 승인으로 바꾼다 | 기각. 보안을 약화시킨다 |
| **MES 를 일반 권한으로 띄운다** | **채택.** `__COMPAT_LAYER=RunAsInvoker` 로 매니페스트의 관리자 요구를 무시한다. 권한을 **내리는** 것이라 UAC 우회가 아니다 |

**대가.** 일반 권한으로 뜬 MES 는 `Program Files` 에 쓰는 자동 업데이트를 못 한다.
업데이트가 뜨면 사용자가 원래 바로가기로 한 번 띄워 받고, 닫은 뒤 다시 `launch` 한다.

**`launch` 를 화면 클릭이 아니라 바로가기 실행으로 만든 이유.**
시작 메뉴를 눌러 띄우는 것과 같은 결과(ShellExecute)를 화면 없이 얻는다. 화면 배치·해상도에 안 흔들리고,
MSI 광고 바로가기·인자·작업 폴더가 바로가기에 적힌 그대로 적용된다.

**새로 뜬 창을 실행 파일 이름이 아니라 "띄운 뒤 새로 생긴 창"으로 찾는 이유.**
- 사이트 바로가기가 MSI 광고 바로가기라 대상이 `C:\Windows\Installer\{GUID}\...exe`(아이콘 파일)로 보였다.
- 같은 실행 파일을 인자·설치 폴더만 달리해 사이트별로 쓴다. 이름으로 "이미 떠 있다"를 판단하면 틀린다.
- 대신 그사이 다른 프로그램이 창을 띄우면 같이 잡힌다(코드에 `ponytail:` 로 표시).

**로그인은 사람이 한다.** 비밀번호는 Claude 가 넣지 않는다. `launch` 는 로그인 창까지 띄우고 멈춘다.
새 창은 처음 한 번 앞으로 나올 수 있다 — 어차피 사람이 로그인해야 하는 순간이다.

## 안전 원칙

- **`--bg` 가 실패하면 멈춘다.** 앞으로 가져와 누르는 걸로 넘어가지 않는다. 넘어가면 요구 1 이 깨지고, 키가 엉뚱한 앱으로 새는 원래 사고가 돌아온다.
- **보내기 전에 권한을 비교한다.** 대상이 더 높으면 "관리자 권한으로 떠 있다"로 멈춘다. 조용히 버려지는 것보다 낫다. `--focus` 입력도 창을 앞으로 가져오기 **전에** 멈춘다.
- **같은 제목 창이 여럿이면 다룰 수 있는 것(권한이 높지 않은 것)을 고른다.** 관리자로 뜬 것과 `launch` 한 것이 같이 있을 때 앞에 있는 관리자 창을 잡지 않게.
- **포커스 칸이 그 창 밖이면 입력하지 않는다.** 같은 앱의 다른 대화상자에 글자가 들어가지 않게.
- `--bg` 와 `--focus` 는 같이 못 쓴다.

## 그래서 의미가 있나

있다. 보기·누르기·넣기·확인이 **전부** 창을 앞으로 가져오지 않고 된다.
남는 조건은 "누를 버튼 자리가 화면 어딘가에 보일 것", "최소화하지 않을 것", "MES 를 `launch` 로 띄울 것" 셋이다.
사람은 한 모니터에서 일하고, Claude 는 다른 모니터의 MES 를 다룬다.

## 확인한 것 / 아직 못 한 것

확인:
- 시험 창(WinForms)을 다른 창이 포그라운드로 덮은 채: 입력칸 클릭, 한글 입력, 버튼(안 덮인 쪽), 가려진 부분 캡처, 포커스 안 뺏김 — `test_rc.py`.
- 실제 MES: 관리자로 뜬 것은 보내기 전에 멈춤. `launch` 로 일반 권한 로그인 창이 뜸. 그 창을 앞으로 안 가져오고 캡처.
- 덮인 MES 버튼(직접 그린 것)은 안 눌림 — 한계 1 그대로.

아직:
- 로그인 뒤 업무 화면에서 직접 그린 메뉴·버튼이 `click --bg` 로 눌리는지.
- DevExpress 그리드 셀·편집기에 `click --bg` → `type --bg` 가 들어가는지(셀 편집기는 눌러야 생기는 자식 창이다).
- 일반 권한으로 뜬 MES 가 업무 기능 중 관리자를 요구하는 것이 있는지.
